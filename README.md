# プロジェクト工程ボード

複数プロジェクトの進み具合を、1プロジェクト＝1行の「横一列」ガントチャートで見渡すための Web アプリです。
営業・メカ・電気・CS（カスタマーサポート）などの工程ごとに、担当者と期間を色分けして表示します。

- 開発環境: Node.js + React (Vite)
- データはブラウザの localStorage に保存されます（サーバー不要・インストール不要）

## 起動方法

```bash
npm install     # 初回のみ
npm run dev     # 開発サーバー起動 → http://localhost:5173
```

本番用ファイルを作る場合:

```bash
npm run build         # dist/ に出力（Webサーバーに置く場合）
npm run preview       # 出力したファイルの動作確認
npm run build:single  # release/project-board.html を出力（HTML 1ファイル）
```

## 主な機能

| 機能 | 内容 |
| --- | --- |
| 横一列のガント | 1プロジェクト＝1行。行の中に工程ごとのレーンを並べて表示。行全体の期間も細い帯で表示 |
| プロジェクトの追加 | ツールバー右上の「＋ プロジェクト追加」で必ず最下行に追加され、そのまま詳細パネルが開く |
| 並べ替え | 行をドラッグ＆ドロップ。一番上の行は番号が金色で強調 |
| 担当が分かる | 左側に「工程＋担当者名」バッジ、タイムラインは工程ごとの色分けバー |
| **工程で強調** | ツールバーのドロップダウンから工程を選ぶと、その工程だけ濃く表示。**複数選択でき**、工程が増えてもツールバーは1段のまま（一覧はスクロール、各工程の使用プロジェクト数つき） |
| **工程の追加・削除** | 工程（担当区分）は**プロジェクトごとの持ち物**。詳細パネルの中で追加・改名・色変更・並べ替え・削除ができ、**他のプロジェクトには一切影響しません**。新規プロジェクトは 営業／メカ／電気／CS の4工程で始まります |
| **1工程に複数の担当** | 同じ工程に担当者・期間を何件でも追加でき、**期間が重ならなければガントの同じ列に横並び**。列が無駄に増えません。既にある工程名で「工程を追加」した場合も、新しい列を作らずその列に担当を足します |
| **立ち上げ日** | プロジェクトごとに立ち上げ日を設定でき、ガント上に赤い ◆ と破線で表示 |
| **Slack スレッドのリンク** | プロジェクト名の右に `#` アイコン（18px角）を表示。クリックで該当スレッドを新しいタブで開く。長い URL は画面に出さず、マウスを乗せたときだけ表示 |
| **フォルダのリンク** | Slack アイコンの右にフォルダアイコン（同じ18px角）。**URL ならクリックで開く**（ダイレクトクラウドの画面）。フォルダのパスを入れた場合は**クリックでパスをコピー**（エクスプローラーに貼り付けて開く）。`tools/` の `.reg` を入れた PC なら、パスを `openfolder:` に変換して**1クリックでエクスプローラー起動**も可能 |
| **TODO のホバー表示** | ガントの**バー（グラフ）にマウスを乗せると、その工程の TODO 一覧**がポップアップ表示（TODO が無い工程では出ません） |
| **進捗の自動同期** | 工程に紐づく TODO があれば「完了数 ÷ 件数」がその工程の進捗になり、ガントのバーにも反映。TODO が無い工程だけスライダーで手入力 |
| TODO リスト | **工程タブで切り替えて表示**（末尾の「すべて」タブで全件表示）。開始日〜終了日を付けて登録でき、終了日を過ぎた未完了は赤字、達成率をバー表示 |
| 完了ページ | 上部タブ「完了」に移動。検索・詳細表示・「進行中に戻す」が可能 |
| 表示の切替 | 日／週／月の目盛り、今日を示す赤い縦線、土日の網掛け、「今日へ」ボタン |
| **書き出し / 読み込み** | 画面右上のボタンでデータを JSON ファイルに保存・復元。共有フォルダ経由での受け渡しやバックアップに使える |

## 使い方

1. **プロジェクトを追加** — ツールバー右上の「＋ プロジェクト追加」。最下行に追加され、右の詳細パネルが開きます。
2. **基本情報を入力** — プロジェクト名・客先・**立ち上げ日**・**Slack スレッド**・メモ。
   Slack はスレッドのリンクをコピーして貼り付けるだけです（Slack のメッセージ右上「…」→「リンクをコピー」）。
3. **担当と工程を入力** — 工程ごとに「担当者名・開始日・終了日」を入力すると、その場でガントバーに反映されます。工程が足りなければ、その下の「＋ 工程を追加」で追加できます（このプロジェクトにだけ増えます）。
4. **TODO** — 詳細パネル下部の工程タブを選んで追加します。選択中の工程に紐づくので、その工程の進捗が TODO の完了率から自動計算されます。
5. **確認** — ガントのバーにマウスを乗せると、その工程の TODO 一覧がポップアップします。
6. **並べ替え** — 行を上下にドラッグします。一番上が最優先です。
7. **完了** — 詳細パネルの「✓ 完了にする」で完了ページへ。戻すときは完了ページの「進行中に戻す」。

## Slack スレッド / フォルダのリンク

詳細パネルの「Slack スレッド」「プロジェクトのフォルダ」に入力すると、プロジェクト名の右に
小さなアイコン（18px角）が並びます。ガントの行・完了ページ・詳細パネルの3か所に出ます。

| アイコン | 内容 |
| --- | --- |
| `#`（紫） | Slack のスレッドを開く |
| フォルダ（橙） | プロジェクトの保管フォルダを開く |

- URL は長いので**画面には表示しません**。アイコンにマウスを乗せるとツールチップで全体を確認できます
- 空欄にすればアイコンは消えます

### フォルダの指定方法（2通り）

**① ダイレクトクラウドの URL（おすすめ）**

ダイレクトクラウドで目的のフォルダを開き、**アドレスバーの URL をコピーして貼り付け**ます。
アイコンをクリックすると、新しいタブでそのフォルダが開きます。

**② フォルダのパス**

`D:\共有\solution\A020076_…` や `\\サーバー名\共有名\A案件` のようなパスも貼り付けられます。
この場合、アイコンをクリックすると**パスをクリップボードにコピー**します。
エクスプローラーのアドレス欄に貼り付け（Ctrl+V → Enter）でフォルダが開きます。

> **なぜクリックで直接開かないのか**
> ブラウザのセキュリティ上、Web ページからエクスプローラーを起動することはできません。
> `file://` のリンクにしても、ブラウザ内にフォルダ一覧が表示されるだけです。
> パスを1クリックで開きたい場合は、下の「`openfolder:` を使う」を参照してください。

**③ `openfolder:…`（パスを1クリックで開く／要インストール）**

後述の `.reg` を入れた PC でだけ使えるリンクです。
② のパスを入れると詳細パネルに **「1クリックで開ける形式に変換」** ボタンが出るので、押すだけで変換されます。

`javascript:` など危険な形式は無効として扱い、リンクにしません。

> DirectCloud Drive の `dcboxdrive://` は、Windows の登録内容に `"%1"`（引数の受け渡し）が無いため、
> アプリが起動するだけでフォルダの指定はできません（社内PCのレジストリで確認済み）。
> そのため本アプリでは使いません。

### `openfolder:` を使う（パスを1クリックで開く）

<span style="color:#c00">**導入には各PCでのレジストリ登録が必要です。情報システム部門の承認を得てから配布してください。**</span>

**入れ方**（PCごとに1回だけ。管理者権限は不要）

1. `tools/openfolder-protocol.reg` をダウンロード
2. ダブルクリック → 「はい」で登録
3. ブラウザを開き直す

**外し方**: `tools/openfolder-protocol-uninstall.reg` をダブルクリック

**使い方**

1. 詳細パネルの「プロジェクトのフォルダ」に `D:\共有\solution\A020076_…` を貼り付け
2. 下に出る **「1クリックで開ける形式に変換」** を押す → `openfolder:D:/共有/solution/A020076_…` になる
3. フォルダアイコンをクリック（初回はブラウザが「このサイトは openfolder を開こうとしています」と確認します）

**安全のための制限**

登録されるコマンドは、渡されたパスが次の条件をすべて満たすときだけエクスプローラーを開きます。

- `C:\` `D:\` のような**ローカルのドライブレターで始まる**こと
- **実在するフォルダ**であること（`Test-Path -PathType Container`）

したがって、

- ファイルは開かない＝**プログラムは一切実行されません**
- `\\サーバー名\…`（UNC）は**あえて弾いています**。認証情報を外部サーバーに送らせる細工を防ぐためです
- 登録先は `HKEY_CURRENT_USER` のみで、他のユーザーや PC 全体の設定は変更しません

変換したリンクを含む JSON を他の人と共有した場合、
`.reg` を入れていない PC ではクリックしても何も起きません（エラーにもなりません）。

## 工程（担当区分）について

**工程はプロジェクトごとに独立しています。** あるプロジェクトで工程を足しても、他のプロジェクトには増えません。
操作はすべて、プロジェクトを開いた右の詳細パネル「担当と工程」で行います。

- **追加**: 一番下の入力欄に工程名（例：修正対応、据付、試運転）を入れて「＋ 工程を追加」。
  **既にある工程名を入れた場合は列を増やさず、その工程に担当が1件追加されます**
- **担当を足す**: 各工程の「＋ 担当を追加」。担当者名と期間を入れると、
  **期間が重ならなければ同じ列に横並び**で表示されます（例：メカ 佐藤 4月〜5月／メカ 中村 6月〜7月）。
  期間が重なるときだけ、その工程の中で段が増えます
- **改名**: 工程名をそのままクリックして書き換え
- **色の変更**: 工程名の左の色見本をクリック
- **並べ替え**: `↑` `↓`。ガントのレーンの順番もこれに従います
- **削除**: `×`。担当者・期間も一緒に削除され、その工程が付いた TODO は「工程なし」に戻ります（TODO 自体は消えません）

新規プロジェクトは 営業／メカ／電気／CS の4工程で作られます。不要な工程は削除、足りない工程は追加してください。

ガントの**行の高さは、その行の工程数に合わせて変わります**。工程を減らせば行も低くなり、
増やせばその行だけ高くなります（他のプロジェクトの行はそのままです）。

ツールバーの「工程で強調」は、全プロジェクトの工程を**名前ごとにまとめて**一覧にします。
「営業」を選べば、どのプロジェクトの営業工程も一度に強調されます。複数の工程を同時に選ぶこともできます。
各工程の右の数字は、その工程を使っているプロジェクトの数です。

## ダイレクトクラウド（共有フォルダ）で使う

サーバーを用意せずに社内で共有したい場合の手順です。

### 1. HTML 1ファイルを用意する

ビルド済みのファイルを**リポジトリに含めてあります**。GitHub から直接ダウンロードできます。

1. GitHub でこのリポジトリを開く
2. `release/project-board.html` を開く
3. 右上の **Download raw file**（下向き矢印のアイコン）で保存

自分でビルドする場合は次のコマンドです（同じファイルが `release/` に上書き出力されます）。

```bash
npm run build:single
```

約250KBの HTML が1つだけできます。JavaScript も CSS も中に埋め込まれているので、
**このファイル単体で動きます**（インストール不要、ネット接続も不要）。

### 2. 置いて配る

`project-board.html` をダイレクトクラウドに置きます。使う人は

- ダウンロードして**ダブルクリック**
- または同期フォルダ／マウントしたドライブ上で**直接ダブルクリック**

これだけで開きます。アプリを更新したいときは、この HTML 1つを差し替えます。

### 3. データの受け渡し

**データはファイルを開いた人のブラウザに保存される**ので、そのままでは共有されません。
JSON ファイルでやり取りします。

- 入力する人: 画面右上の **「書き出し」** → `project-board_2026-08-01.json` を共有フォルダに保存
  （Chrome / Edge では保存先を選べるので、共有フォルダの同じファイルに上書きできます）
- 見る人: **「読み込み」** でそのファイルを選ぶ → 手元のデータが置き換わります

読み込み前には件数を出した確認ダイアログが出ます。書き出したファイルはそのままバックアップにもなるので、
日付入りのファイルを何世代か残しておくと安心です。

### 注意点

- **同時編集はできません。** 入力担当を1人に決め、他の人は読み込んで見る運用にしてください
- ファイルを直接開く（`file://`）とき、ブラウザの設定やキャッシュ削除でブラウザ内のデータが消えることがあります。
  **こまめに「書き出し」してください**
- 全員がリアルタイムに同じデータを見たくなったら、`src/lib/storage.js` をサーバー保存に差し替えます
  （画面まわりのコードはほぼそのまま使えます）

## データについて

保存先はブラウザの localStorage（キー: `project-gantt-board:v1`）です。
別の PC やブラウザとは共有されません。共有が必要になった場合は、この保存部分（`src/lib/storage.js`）を
サーバー API に差し替える構成にしています。

保存形式が変わっても、古いデータは読み込み時に自動で移行されます
（工程が全プロジェクト共通だった頃のデータは、共通工程 + そのプロジェクト固有の工程をまとめて
各プロジェクトの工程として引き継ぎます。TODO の「期限」は「終了日」として引き継ぎます）。
